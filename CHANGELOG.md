# Changelog

All notable changes to this public preview. Newest first. The version is the one in `Cargo.toml`
(`make bump-version`); every build is also stamped with its date and commit (Admin > About, `rustbucket version`).

## Unreleased (2026-11-28, after the first public commit)

### Added
- **Live editor for text files** (`.md .markdown .txt .sh .bash .py .json .yml .yaml .conf`): several people edit the same file at the
  same time, Etherpad style. Everybody who can read the file sees the changes live; only users with change permission can type, and the
  server enforces that (a reader's forced updates are dropped). Saved automatically (5 s after the last edit, at the latest after 60 s,
  and when the last person leaves) through the normal upload path, so every save is a version and sync clients see it; a script keeps
  its executable bit. A change made by a sync client while the file is open is taken over. Built on `yrs` (Yjs) on the server and
  CodeMirror 6 in the browser, over a WebSocket (`/apps/files/edit/ws`) that checks the page's origin and a CSRF token. Limits: 2 MiB per
  text (`RUSTBUCKET_EDITOR_MAX_BYTES`), 20 people per file, files with NUL bytes or invalid UTF-8 are refused. Switch off with
  `RUSTBUCKET_EDITOR=false`. Behind your own reverse proxy it needs WebSocket support (`docs/install.md`; the standalone nginx has it).
- **Undo and Redo over everybody's changes**, each button must be held for one second (so a rollback of other people's work cannot happen
  by accident; there is deliberately no Ctrl+Z), and **Save & close**, which saves at once and returns to the file list.
- **Direct editing for the Nextcloud mobile apps**: the server now advertises `files.directEditing`, so the Android app opens a tapped text
  file in the same editor instead of only showing it. The app asks for a one-time URL (valid 5 minutes, once); opening it creates a
  separate "direct" session that works for that one file in the editor and for nothing else (not the file list, DAV or the API).
  Format checked against stock Nextcloud 35. New migration `0007` (two small tables).
- **Image and video viewer**: a click or tap on a PNG, JPEG, GIF, WebP, BMP, WebM or MP4 file shows it full screen instead of
  downloading it. Zoom with the mouse wheel, pinch, `+`/`-` or double click/tap, move it when zoomed, `X` (top right) or Esc closes,
  arrow keys go to the next item. *Download* moved to the row menu. The content security policy gained `media-src 'self'`.
- **Dark mode**: a button in the top bar switches between auto (follows the system), dark and light; the choice is remembered and applied
  before the page is painted. The editor follows. The login page follows the system only.
- **JavaScript supply-chain checks**: all JavaScript is listed with versions and licenses in `docs/js-dependencies.md` (generated by
  `make js-inventory`); `make audit-js` runs `npm audit` and checks the registry signatures; `make editor-bundle` rebuilds
  `static/editor.js` from the lockfile with `npm ci --ignore-scripts` in a pinned container and `make editor-check` proves the committed
  file is exactly that. CI runs both daily. Renovate watches the npm packages (7 days minimum age, no automerge).
- **The image is now Alpine (musl) instead of Debian, one Dockerfile**: the full smoke test, the real Nextcloud client suite and the
  Trivy scan pass, and the image is about 30 % of the size (standalone 205 MB -> 60 MB, bare server 174 MB -> 45 MB; server memory
  after a 200 MB transfer 44 MB -> 10 MB; 200 MB download on loopback about 20 % slower, no difference over a real network).
  The runtime image carries GNU tar and bash (`make backup`, entrypoint). Base images are pinned by digest, `apk upgrade` re-runs daily.
  The last Debian Dockerfile is kept for reference in `docs/shelf/`. Details and caveats: `docs/alpine.md`.
- **Security scans in the Makefile and CI**: `make audit-deps` (`cargo audit` for RustSec advisories + `cargo deny` for advisories, licenses,
  bans and sources) and `make scan-image` (Trivy, pinned version, over the built image: Alpine packages incl. nginx/openssl/curl, and secrets
  in layers; fails on fixable HIGH/CRITICAL findings). CI runs both daily as well, because advisories appear without any code change.
  SonarQube does not analyze Rust, so these are the Rust-side checks next to `clippy -D warnings`.
- **`#![forbid(unsafe_code)]`** in the crate: our code uses none, and the compiler now guarantees it stays that way.
- **Left menu in the web client**: *My own files* (only what you own), *Shared with me* (incoming shares with owner,
  permission and date), *Shared* (what you share with others, with recipients and permissions) and *Trash*. The views
  are `?view=shared-with-me|shared`; no `view` means your own files, so old links keep working. Sync clients and
  WebDAV are unchanged: they still see incoming shares at the root, only the web view separates them. At phone width the
  menu becomes a row.
- **Share as an icon, a "..." menu for the rest, and multi-select**: every row has a Share icon button first
  (highlighted when the item is shared) and a "..." menu with Rename, Move, Versions and Delete (Delete keeps its
  "Sure?" click). Every row has a checkbox and the header a select-all; a bar above the list offers Move (target folder) and
  Delete (confirmation click) for the selection. An action is offered only when every selected item allows it; failures
  are listed by name. On a phone a row becomes two lines with the icons beside the name.
- **Version and build number**: version from `Cargo.toml` (`make bump-version V=X.Y.Z|patch|minor|major`, which also
  updates `Cargo.lock` and `fuzz/Cargo.lock`); the image is stamped with the UTC build date and the git commit
  (`make image`); the build id is a short hash of both plus the version. Shown to administrators in a new **Admin menu**
  (Users, About, and the version line), on a new **About page** (`/settings/about`), by `rustbucket version`, in the
  `rustbucket_build_info` metric and as OCI image labels.
- `make smoke` tests a chunked upload (WebDAV chunking v2) through nginx with curl: session, out-of-order chunks, a
  refused assembly with a missing chunk, the final MOVE, byte comparison and cleanup. It also checks that the build
  number is stamped into the image.
- `make user` (and the other make targets) are described for AI agents in `CLAUDE.md`.

### Fixed
- **zlib CVE-2026-85091 (HIGH) in the image**, found by the new `make scan-image`: the pinned Debian base image still had the old
  zlib while the fix was already in Debian's security repository (libc6 and openssl updates were pending too). The image now
  applies the Debian security updates at build time (`apt-get upgrade`, re-run daily through a date build argument that
  `make image` passes), so it no longer depends on when the base image happens to be rebuilt.
- **A failed upload could vanish silently** (SonarQube `javascript:S9383`, two findings): the file chooser and the drag-and-drop
  handler started the async upload without handling a failure, so an unexpected error was an unhandled rejection with no
  message. They now go through one helper that shows "Something went wrong. Please reload the page and try again."
- **Stale scripts and styles after an update**: static files are cached for an hour and were keyed only by the Cargo
  version, so a new image without a version bump could serve a new page with old JavaScript or CSS. The asset links now
  carry the build id, which changes with every build.
- **`make user ADMIN=0` created administrators**: `$(if $(ADMIN),--admin)` treated any non-empty value as true. Now
  `0`, `no`, `false` and empty mean a normal user; `ADMIN=1` (or any other value) makes an administrator.
- **Credential files in the working tree**: `.env_*` and `*.env` are git-ignored (`.env.example` stays tracked).
- The generated SonarQube report (`security_audit.md`, contains local paths) is git-ignored.

### Changed
- SonarQube: the reviewed findings that are accepted by design are recorded in `sonar-project.properties`
  (`Web:S5247` on `templates/files.html`: the `|safe` embeds our own already-escaped fragment; `Web:S9379` on the two login
  pages: autofocus on the username field, the login pages allow no script so JavaScript cannot set the focus).
- Tests: a web test for the three views (redirects, escaping, unsharing), one for the icon/menu/checkbox markup and the
  permission flags, one for the Admin menu, About page and asset links; Chromium tests for switching views, multi-select
  (move, delete, trash) and the phone layout; the metrics test checks the full `rustbucket_build_info` labels.

## First public commit (2026-11-21)

Single-container standalone image (the server plus nginx with a self-signed certificate), driven by the Makefile.
Fixed while preparing it:
- **Trusted-proxy check used the wrong address**: behind a trusted proxy and without a pinned `RUSTBUCKET_BASE_URL`, the
  login flow handed out `http://` URLs and cookies lacked the `Secure` flag, because the handlers passed the forwarded
  *client* address (`X-Forwarded-For`) to the trust check instead of the TCP peer. New extractor `auth::Peer` for these
  decisions; `ClientIp` stays for rate limits and logs. Regression test:
  `forwarded_proto_is_honoured_from_a_trusted_peer_only`.
- `make restore` only fills empty volumes and refuses to run over existing data; `make purge` needs `CONFIRM=1`.
- The login throttle cannot be dodged with a forged `X-Forwarded-For` (nginx overwrites the header; tested in
  `make smoke`).
